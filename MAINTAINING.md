# Maintain the marketplace

This repository installs as one bundle. `claude/` and `codex/` hold client-specific guides, demos, skills and setup entry points. `shared/` holds the workspace snapshot, icon, common generator and deploy skill. Both root marketplace catalogs must point to `./`; installing a client subfolder alone leaves out shared resources.

The root `.claude-plugin/plugin.json` selects `claude/skills` plus `shared/skills`. The root `.codex-plugin/plugin.json` selects `codex/skills` plus `shared/skills`; it uses Codex's supported compatibility format for explicit skill directories. Do not add a root portable `plugin.json` or default `skills/` without verifying client discovery again. Keep `aguru-builder` and `aguru-workflow-builder` as the marketplace and plugin names.

## Publish an update

1. Build the versioned source with `pnpm --filter @aguru/builder-kit build` in an authorized Aguru checkout. The standalone npm package and this marketplace are separate distributions; publishing one does not update the other.
2. Refresh `shared/assets/builder-kit/` from the generated Codex bundle, including hidden files. It contains the complete workspace snapshot. Do not keep a second workspace copy under either client. Copy the icon to `shared/assets/icon.png` and the generated license to root `LICENSE`.
3. Refresh each client's four skills (`setup`, `new-workflow`, `add-scm-need`, `run`) from its generated bundle. Keep the identical `deploy` skill once in `shared/skills/`. Preserve the root-aware setup paths: Claude invokes `claude/scripts/create-workspace.mjs`; Codex resolves the installed root three directories above its setup skill folder and invokes `codex/scripts/create-workspace.mjs`.
4. Keep the shared generator aligned with the source generator, preserving its `workspaceExcludes` parameter and recursive copy filter. Both client entry points call it; Claude excludes `.claude/skills` and Codex copies the full snapshot. Preserve the public guides and check demo links. Never copy a generated marketplace or manifest over the root catalogs and skill-path settings.
5. Increment both client manifests together when plugin contents change. Their version identifies this marketplace release; the bundled workspace can retain its npm kit version when only packaging changes. Version `1.0.2` uses the `1.0.1` workspace snapshot. Do not reuse a published plugin version.
6. Validate Claude with `claude plugin validate --strict .`, then register and install using a temporary `CLAUDE_CONFIG_DIR`. Inspect its installed skill inventory: five skills, with Claude setup and one shared deploy skill. Use Codex's local plugin details to check the same inventory with Codex setup and the configured onboarding skill. Verify shared icon and generator paths in the installed copies.
7. Exercise each setup entry point outside the repository. Verify new nested destinations work and existing destinations are rejected without modifications. Install workspace dependencies and validate shipped templates. Check source leaks, credentials, local links and the generated output against both original bundles.
8. Commit using Conventional Commits and test registration from GitHub after pushing. Tag the version and publish a release with a ZIP of the complete repository, including `claude/`, `codex/`, `shared/` and hidden manifest/catalog folders, plus its SHA-256 checksum. Do not distribute a client folder on its own. Release archives are immutable snapshots; older releases can have a different layout or include only one client.

This GitHub marketplace does not imply approval or listing in OpenAI's or Anthropic's public directories.
